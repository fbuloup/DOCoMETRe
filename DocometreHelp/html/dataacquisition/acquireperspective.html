Acquire Perspective

The Acquire perspective is the one used to run an experiment: it launches acquisition processes on the real time system (ADwin, Arduino) and displays acquired signals in real time charts. It is made of four parts:

  • the tool bar, used to select the item to run, to move between trials and to start or stop acquisition;
  • the state zone, at the top of the window, which shows what is going to run or is running (item, experiment, subject, session, trial and process);
  • the real time charts zone, which occupies the rest of the window;
  • the status bar, at the bottom of the window, which shows real time system workload, elapsed time and messages.

All the actions needed during acquisition can also be done from the keyboard: see keyboard shortcuts and full screen mode.

Tool bar

When the Acquire perspective is active, the main tool bar contains the following buttons, from left to right:

Button Action
Select item to run Opens a dialog to choose what to run: a process, a subject, a session or a trial. The item can also be selected in the Experiments view. The chosen item is displayed in the state zone ("Item to run").
Go to beginning Moves to the first trial to run.
Previous trial Moves to the previous trial.
Next trial Moves to the next trial. When there is no next trial, the first runnable trial not yet done is chosen.
Go to end Moves to the last trial to run.
Run / Stop Runs the selected item. While the experiment is running, this button becomes a Stop button. Shortcut: F9.

The trials navigation buttons change the trial that will be run next (it is displayed in the state zone). The Run / Stop button is disabled when the selected item cannot be run (for example a trial with no associated process).

State zone

The state zone is the line just above the charts. It gives:

  • Item to run: full path of the selected item (process, subject, session or trial);
  • Experiment, Subject, Session: where the trial to run belongs;
  • Trial: current trial, followed by the number of trials in the session;
  • Process: name of the acquisition process run by this trial.

"N.A." (not available) is displayed when a value does not apply, for example the subject when a process is run on its own.

Real time charts zone

Charts are created at the beginning of each trial, from the charts defined in the acquisition configuration file associated with the process (oscilloscope, XY, XYZ, gauge, tank or image charts). Their arrangement (number of columns, horizontal and vertical spanning) is also defined in this file. Charts of the last trial stay displayed when acquisition is over.

This zone can be displayed alone on the whole screen: see full screen mode.

Status bar

During acquisition, the status bar at the bottom of the window shows:

  • Workload : xx% - Time : yy: real time system processor workload and elapsed time of the current trial. A workload close to 100% means the real time loop period is too short for what the process has to do.
  • Pause pending...: a pause has been requested (see Pause below); the experiment will stop after the current trial.
  • error messages, for example when data are lost during transfer between the real time system and the computer. Details are then written in the process diary.

Keyboard shortcuts

The following shortcuts are only active in the Acquire perspective. F9 and F11 are ignored when a dialog is opened (trial validation, next trial, stop confirmation...).

Shortcut Action
F9
or Ctrl+Shift+Enter (Cmd+Shift+Enter on macOS)		 Run the selected item, or stop it if the experiment is running (same as the Run / Stop button).
Esc Stop the running experiment.
Pause
or Cmd+P on macOS		 Pause the running experiment: the current trial is completed, then the experiment stops ("Pause pending..." is shown in the status bar). Run it again to go on with the next trials.
F11
or Ctrl+Shift+F (Cmd+Shift+F on macOS)		 Enter or leave full screen mode.

When stopping (Esc or F9), a confirmation dialog may be displayed and the trial is stopped immediately or at its end, depending on DOCoMETRe preferences.

On laptop keyboards, function keys may require the Fn key to be pressed: the alternative shortcuts avoid this.

Full screen mode

Full screen mode displays the real time charts alone on the whole screen, for example on a screen in front of the subject. The window goes full screen and the following elements are hidden:

  • window title bar and borders;
  • menu bar (on macOS, it appears again when the mouse reaches the top of the screen);
  • tool bar and perspectives bar;
  • state zone;
  • status bar.

Keyboard shortcuts still work in full screen mode, and dialogs displayed between trials appear over the charts. Full screen mode can be entered before or during acquisition. It is automatically left when another perspective is selected.

A typical use is:

  1. select the item to run (tool bar or Experiments view);
  2. press F11 to display charts in full screen;
  3. press F9 to run the experiment;
  4. press Esc or F9 to stop it, or Pause to stop after the current trial;
  5. press F11 to come back to the normal display.

The full screen is displayed on the screen where the window is: move the window to the right screen before pressing F11.
