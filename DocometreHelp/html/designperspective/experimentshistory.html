Experiments History

The history of an experiment records snapshots of the experiment: a snapshot is a copy of the whole experiment (configurations, processes, protocol, parameters files, data files, diaries, data processings, charts and DOCoMETRe properties of the resources) at a given time, with a name and an optional description. You can then look at what changed between snapshots, go back to the content of any snapshot, and go forward again: restoring a snapshot never deletes another snapshot.

The history is local: it is stored in a hidden .git folder of the experiment folder (DOCoMETRe uses Git internally, but you never need to know or use Git). It is enabled experiment by experiment.

The history is an experimental feature, disabled by default. To use it, check Use experiments history (experimental) in Options > Preferences > History (see preferences). When it is not checked, histories which already exist can still be viewed (Snapshots view, differences of files, indicators of the Experiments view), but the history can't be enabled on an experiment, and snapshots can't be created, restored or deleted (no automatic snapshot either).

Enabling the history

The history must first be enabled in preferences (see above). Then, in the Experiments view, right click on the experiment (or on any of its resources), then History > Enable history.... After confirmation, DOCoMETRe creates the history of the experiment and its first snapshot, named "History enabled". The Snapshots view is then opened.

The History sub menu also contains Create a snapshot..., Show history and Disable history..., depending on whether the history of the experiment is enabled.

The Snapshots view

The Snapshots view (History > Show history) shows the history of the experiment selected in the Experiments view or in the Subjects view. Its header gives the name of the experiment and its number of snapshots.

The first row of the table is the Current state of the experiment: it gives the number of changes that are not saved in a snapshot yet ("3 change(s) not saved"), or "No change since No.N". The other rows are the snapshots, the most recent first, with their number, name, date, type and author. Types are:

TypeMeaning
ManualSnapshot created by the user.
AutomaticSnapshot created by DOCoMETRe, for example to save unsaved changes before a restoration, a deletion or a renaming (see Automatic snapshots).
RestorationSnapshot created by the restoration of another snapshot or of a file.

Snapshot numbers never change and are never reused: when a snapshot is deleted, its number simply disappears from the list.

The details pane shows the selected row: name, date, author, type, "restoration of No.N" for a restoration, "same content as No.N" when several snapshots have exactly the same content, the description, and the list of files:

  • for the Current state: the files added, modified or deleted since the last snapshot;
  • for a snapshot: the files added, modified or deleted by this snapshot, compared to the previous one.

Two special files can appear in these lists: (experiment properties), the file that holds the DOCoMETRe properties of the resources (trials states, default DACQ configuration, descriptions...), and (folders list), which records the folders of the experiment, so that empty folders (trials not acquired yet for example) are restored too.

The tool bar of the view contains Enable history, Create a snapshot and Refresh. Refresh also takes into account files modified by other programs. Disable history is in the menu of the view.

Indicators of the Experiments view

In the Experiments and Subjects views, historized experiments show the number of their last snapshot and, if any, the number of unsaved changes, for example MyExperiment [No.5, 3 change(s)]. A > prefix marks the experiment, the folders and the files that changed since the last snapshot. These indicators are updated about one second after each change.

Creating a snapshot

Use History > Create a snapshot... (or the tool bar of the Snapshots view), give a name and, optionally, a description. If editors are modified, you are asked to save them first: a snapshot contains the files of the experiment, not the unsaved contents of editors. If nothing changed since the last snapshot, no snapshot is created. Snapshots can't be created while an acquisition is running.

Create a snapshot at each important step: before a new session of acquisitions, after the validation of a configuration, before and after a data processing...

Showing the differences of a file

In the list of files of the details pane, double click on a file (or right click > Show differences). The lines removed are shown in red, the lines added in green. For a snapshot, these are the changes saved by this snapshot; for the Current state, the changes since the last snapshot.

Differences can only be shown for text files: DOCoMETRe files are text files when the XML serialization is enabled in the general preferences (default). Data files (samples...) are binary files, and files larger than 5 MB are not compared.

Restoring a snapshot

Select a snapshot, then press Restore this snapshot... (or right click on the snapshot). A confirmation dialog lists what will be done and the files that will be replaced, removed or recreated (with a warning when acquisition data files will be removed). Then:

  1. all the editors are closed (you are asked to save the modified ones);
  2. the subjects of the experiment loaded in the math engine are unloaded (modified subjects are saved first if the corresponding box is checked);
  3. the unsaved changes of the experiment are saved in an automatic snapshot ("Automatic save before restoration");
  4. a new snapshot ("Restoration of ...") is created with exactly the content of the restored snapshot, and the files of the experiment are replaced;
  5. the DOCoMETRe properties of the resources are read again and the views are refreshed.

Nothing is lost: to come back to the state before the restoration, restore the automatic snapshot (or the last snapshot before the restoration). Restorations are not possible during an acquisition.

If some files are used by another program (antivirus, file explorer, Python, Matlab...), the restoration may not be complete: a dialog lists these files. Close the programs that use them, then press Retry, or later restore the same snapshot again.

Restoring a single file

In the list of files of the details pane, right click on a file, then Restore this file as it was in No.N.... Only this file is replaced (or recreated, or removed if it did not exist in this snapshot); the rest of the experiment is not modified. As for a whole restoration, all the editors are closed (you are asked to save the modified ones), the loaded subjects that contain the file are unloaded, unsaved changes are first saved in an automatic snapshot and a new snapshot is created.

On the Current state, this command restores the file as it was in the last snapshot: it cancels the changes of this file.

Deleting a snapshot

Right click on a snapshot, then Delete this snapshot.... The snapshot is permanently deleted, including the file versions that only existed in this snapshot (they are listed in the confirmation dialog). The other snapshots keep their contents, names, numbers and dates. The only snapshot of a history can't be deleted: disable the history instead.

When the last snapshot is deleted, two choices are proposed:

  • Delete and go back to No.N: the files of the experiment take again the content of the snapshot that becomes the last one, for example to cancel a restoration. This choice is only available if nothing unsaved would be lost (no change since the deleted snapshot, DOCoMETRe properties such as descriptions or trials states included, no modified editor of the experiment, no modified loaded subject, no acquisition running);
  • Delete and keep current files: the files are not modified, the changes of the deleted snapshot then appear as unsaved changes of the Current state.

Deleting a snapshot that is not the last one never modifies the files of the experiment.

Automatic snapshots

When an experiment is historized, DOCoMETRe creates an automatic snapshot of its unsaved changes before deleting or renaming resources of this experiment, and before deleting diaries and data files of trials, sessions or subjects ("Automatic save before deleting ...", "Automatic save before renaming ...", "Automatic save before deleting diaries and data files of ..."). It also saves unsaved changes before a restoration. An automatic snapshot is only created when there are unsaved changes.

Renaming the experiment itself does not create a snapshot (it does not modify its data): the history follows the experiment under its new name. Deleting the experiment also deletes its history.

Preferences

Options > Preferences > History:

PreferenceMeaning
Use experiments history (experimental)Not checked by default: existing histories can only be viewed, nothing can be modified (no history can be enabled, no snapshot can be created, restored or deleted). The other preferences of the page can only be changed when it is checked.
Author of snapshots, Author e-mailShown in the Author column of the Snapshots view. By default, the name of the session of the computer.
Create an automatic snapshot before deleting or renaming resources of a historized experiment, or deleting its diaries and data filesSee Automatic snapshots (checked by default).
Optimize history storage every N snapshotsThe storage of the history is compacted in background when N snapshots of any type (manual, automatic or restoration) have been created since the last compaction (20 by default, 0: never). It is also compacted after each deletion of a snapshot.

Export and import

When a whole historized experiment is exported (File > Export Experiment..., see Exporting an experiment), the option Include history (snapshots) adds the history to the archive. The archive may then be much larger: the history contains all the versions of the files, acquisition data included. When such a zip archive is imported, the experiment is imported with its history.

Disabling the history

History > Disable history... (or the menu of the Snapshots view) permanently deletes all the snapshots of the experiment (its .git folder). The current files of the experiment are not modified. The history can be enabled again later: it then starts again with a new snapshot No.1.

Notes and limits

  • The history is not a backup: it is stored in the experiment folder, on the same disk. Keep exporting your experiments regularly to another location.
  • Every version of every file is kept, acquisition data included: the size of the history grows with the number of acquisitions. Files that never change (data of finished trials) are stored only once.
  • Files generated when compiling processes (BinSource folders) are not historized.
  • Do not modify the .git folder of an experiment, and do not use Git tools on it.
  • While an acquisition is running, snapshots can't be created or restored, and the history can't be enabled or disabled.
