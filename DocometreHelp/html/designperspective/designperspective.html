Design Perspective

The Design perspective is the one used to prepare an experiment before running it in the Acquire perspective. In this perspective you describe the real time system (ADwin or Arduino), you write the acquisition processes, you organize the experimental protocol (subjects, sessions and trials) and you can inspect the files created during acquisition (data files and diaries).

This page describes the perspective as a whole and the different kinds of files and folders you will handle. The following pages give more details:

  • DACQ configuration: description of the real time system and of its tabs;
  • DACQ process: the program run by the real time system and the tabs of its editor;
  • Testing a process: running a process on its own, without subject, session or trial;
  • Subjects, sessions and trials: organization of the protocol, parameters files and diaries;
  • Data editor: display of acquired signals (samples files);
  • Import and export: exchange of experiments, configurations, processes, data and sessions with other computers or software.

Layout of the perspective

The Design perspective is made of the following parts:

  • the Experiments view, on the left, which shows all the experiments of the workspace as a tree (see below). The Functions view (Options > Show... > Functions View) can be opened in the same place;
  • the Description view, under the Experiments view, which shows the description of the selected resource. The description is given when the resource is created; it can be changed with Edit > Edit description;
  • the editors area, in the center, where files are opened (configurations, processes, parameters files, diaries, data files...). Several editors can be opened at the same time, each one in its own tab. An editor whose content has been modified shows a "*" before its name: save it with File > Save (Ctrl+S, Cmd+S on macOS) or File > Save all;
  • the Console view, under the editors area, where DOCoMETRe writes information, warning and error messages (compilation, loading of data files, etc.).

Views can be closed, moved or resized; Options > Show... opens the Experiments, Description and Functions views again.

When a data editor is active, zoom and pan buttons are added to the tool bar (see Data editor).

Experiments view

The Experiments view shows the content of the workspace: each experiment is a folder of the workspace, and each element of the tree is a file or a folder on the disk. DOCoMETRe associates a type with each of them (configuration, process, subject, session, trial...) which defines its icon, its label and what can be done with it.

  • a double click on a folder expands or collapses it; a double click on a file opens it in the corresponding editor (File > Open does the same for the selected files);
  • the tool bar of the view contains Undo/Redo (for operations such as rename or description changes), Collapse all and Link with editor (when checked, the file of the active editor is selected in the tree);
  • a right click opens the context menu, whose content depends on the selected resources (see below);
  • samples files can be dragged from the view and dropped onto an opened data editor to display several signals together.

Some information is added to the labels of the tree:

Resource Label and decorations
DACQ configuration Name followed by the system, for example MyConfiguration [ADWin] or MyConfiguration [Arduino UNO]. The default configuration of the experiment is marked with an overlay icon.
DACQ process Name followed by the path of its associated DACQ configuration, for example MyProcess [/MyExperiment/MyConfiguration], or "No associated DAQ file".
Subject, session Name followed by the percentage of trials already done, for example Session1 [40%].
Trial Name followed by its start mode, its validate mode and its associated process, for example Trial n°3 [S.Man.][V.Auto.] [/MyExperiment/MyProcess]. Its icon shows whether the trial has been done or not.
Any resource An error (or warning) overlay is displayed on a resource that contains an error (or warning), for example a process that does not compile or a diary that reports a data loss. The overlay is also displayed on all the parent folders.

Files and folders types

The following table lists the types of resources handled in the Design perspective. Most of them are created with DOCoMETRe commands; files copied into the workspace by other means get their type from their extension (Refresh, F5, makes them appear). The type of an untyped resource can be forced with Edit > Set type...

Type On the disk Description
Experiment Folder at the root of the workspace Contains everything related to an experiment: configurations, processes, subjects, data processing files...
Folder Folder Used to organize the content of an experiment. It can contain configurations, processes, subjects and other folders.
DACQ configuration *.daqconf file Description of the real time system: modules, channels, variables and real time charts. See DACQ configuration.
DACQ process *.process file Program run by the real time system, built with graphical blocks and associated with a DACQ configuration. See DACQ process.
Subject Folder A participant of the experiment. Contains sessions.
Session Folder A set of trials run in sequence. Contains trials and possibly a parameters file.
Trial Folder named Trial n°N One run of a process. After acquisition, it contains the diary and the samples files of the trial. See Subjects, sessions and trials.
Process test Folder named test.ProcessName Created when a process is run on its own. Contains the samples files of the test. See Testing a process.
Parameters file *.params file Values of the parameters for each trial of a session (ADwin only). See Parameters files.
Log file (diary) *.log file Events diary written during the run of a process: start and end times, transfers, data losses... See Diaries.
Samples file *.samples file Values of one recorded channel, as 32 bits floating point numbers. Opened with the data editor.
ADW file, Optitrack files, column data files, CSV files *.adw, *.csv, *.txt files Data files from other sources, imported in a subject (see Import and export and Supported data files formats).
Data processing, batch data processing *.dataprocess, *.batchdataprocess files Processing applied to loaded subjects in the Analyse perspective.
XY chart, 3D chart *.chart, *.chart3D files Charts of processed data, used in the Analyse perspective (see XY and 3D charts).
User function *.FUN file Function that can be assigned to a function block of a process (see How to create my own dacq. user function ?).
Saved data save.data, save.mat, *.numpy files Subject data saved by the math engine in the Analyse perspective.

A typical experiment looks like this:

MyExperiment
   MyConfiguration [ADWin]
   MyProcess [/MyExperiment/MyConfiguration]
   test.MyProcess
      Channel1.samples
   MyProcess_diary.log
   Subject1 [50%]
      Session1 [50%]
         Session1.params
         Trial n°1 [S.Man.][V.Man.] [/MyExperiment/MyProcess]
            diary.log
            Channel1.samples
            Channel2.samples
         Trial n°2 [S.Man.][V.Man.] [/MyExperiment/MyProcess]

Names of diaries depend on the language of DOCoMETRe (diary.log in English, journal.log in French).

Associations between resources

Resources are linked together:

  • a DACQ configuration is associated with a system (ADwin or Arduino UNO) when it is created (the "Associate with system" sub-menu of the Edit menu or of the context menu changes it);
  • each process is associated with a DACQ configuration of the same experiment: it can only use the channels and variables declared in this configuration. The association is chosen when the process is created; it can be changed later by selecting one or several processes and choosing the configuration in the Associate with... sub-menu of the context menu;
  • each trial is associated with a process: this is the process run when the trial is run. The association is made when the session is created or edited, or by selecting trials and choosing the process in the Associate with... sub-menu.

One configuration of each experiment can be marked as the default one (context menu > Set as default): it is pre-selected when a new process is created.

Typical workflow

  1. Create an experiment (New experiment).
  2. Create a DACQ configuration, choose the system and describe its modules, channels, variables and real time charts.
  3. Create one or several DACQ processes associated with this configuration and build their algorithm with graphical blocks.
  4. Compile the processes and test them on their own.
  5. Create the subjects, sessions and trials of the protocol, associate a process with each trial and, if needed, add parameters files.
  6. Run the subjects, sessions or trials in the Acquire perspective.
  7. Come back to the Design perspective to check diaries and to inspect acquired signals with the data editor, then process them in the Analyse perspective.

Compilation

The code of a process is generated from its blocks and from its DACQ configuration, then compiled with the tools of the system (ADbasic compiler for ADwin, arduino-builder/avrdude or arduino-cli for Arduino). Compilation is done:

  • automatically, each time a process or a DACQ configuration is saved, when Options > Build automatically is checked (all the processes associated with a saved configuration are compiled again);
  • on request, with Compile in the context menu (selected processes) or Options > Compile... (all the processes of the chosen experiments).

Compilation errors are written in the Console view and shown with an error overlay on the process, on its editor tab and on the parent folders.
