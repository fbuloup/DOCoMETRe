DACQ Process

A DACQ (data acquisition) process file (*.process) is the program run by the real time system during a trial. It is not written as text: it is built with graphical blocks (functions, conditions, loops) linked together, from which DOCoMETRe generates the ADbasic code (ADwin) or the C code (Arduino) and compiles it. A process is always associated with a DACQ configuration, whose channels and variables it uses.

Creating a process

Select an experiment or a folder in the Experiments view, then use File > New > DACQ Process (or the corresponding tool bar button). The wizard asks for the name of the process, its description and its associated DAQ configuration (the default configuration of the experiment is pre-selected). The association can be changed later with the Associate with... sub-menu of the context menu; in that case, check that the channels used by the process exist in the new configuration.

A process can be opened only if its associated configuration exists: the system of the configuration (ADwin or Arduino) defines the editor used.

Process editor and its tabs

The execution of a process is split into three segments, each one edited in its own tab (tabs at the bottom of the editor):

Tab (ADwin / Arduino) When is it executed ? Typical use
Initialize / Initialize Once, before the real time loop starts. Initial values of variables and outputs, configuration of devices. This tab also shows the global declarations.
Event / Loop At each period of the real time loop (the period is the inverse of the global frequency of the DACQ configuration). Acquisition of inputs, computations, generation of outputs, transfers, conditions to end the process.
Finalize / Finalize Once, after the last loop. Reset of outputs, final computations.
ADBasic source code / Arduino Uno source code - Read only view of the generated code (see below).

In the segments, the variable time (rtTime on Arduino Uno R4 WiFi) gives the time, in seconds, elapsed since the beginning of the real time loop: it is managed by DOCoMETRe and can be used in conditions and expressions (for example to stop the process after a given duration).

Palette and blocks

Each segment tab is a drawing area with a palette on its side. The palette contains selection tools (selection, marquee selection) and the Elements drawer:

Element Description
Connection Creation Links a block to the next one: click on the first block, then on the next one. The connections define the order of execution.
If block Conditional block: "IF left operand operator right operand". Operators are >, >=, <, <=, = and <>. It has two outgoing connections: the true branch and the false branch.
Do block Loop block: the blocks between the DO block and its end function are repeated until (ADwin) or while (Arduino) the condition is true. Link the DO block to its first function, link the end function back to the DO block, then double click on this last link to specify the end function.
Function block Executes a function (acquisition, generation, filter, expression, transfer...). A new function block is not yet assigned: right click > Assign to choose its function.
Comment block Free text, ignored by the code generation.

Blocks are created by selecting an element in the palette and clicking in the drawing area; they can be moved and resized with the mouse. The first block of a segment is the one that has no incoming connection: a segment must have only one start block (otherwise a warning says which one is used). Structure errors (IF block without true or false branch, DO block without end function, branches that leave their block...) are reported as warnings with an explanation of how to fix them.

A double click on a block opens its configuration dialog (parameters of the function, condition of an IF or DO block, text of a comment). In text fields, Ctrl+Space displays the list of the available channels and variables.

The context menu of the drawing area contains:

  • Copy, Paste, Undo, Redo (also with the usual shortcuts); blocks can be copied from one process to another;
  • Edit... (same as a double click) and Assign (function of a function block);
  • Toggle activated state: a deactivated block is ignored by the code generation, which is useful to test variants of a process;
  • Delete (also with Del or Backspace);
  • Zoom to Fit page and Zoom to 25%, 50%, 100%, 200%, 300%;
  • Show grid and Block alignment helper (snap to grid). Zoom, grid and alignment states are saved with the process.

Global declarations

The Initialize tab shows a Global declarations box that summarizes the libraries, constants and subroutines declared for the process (its tooltip lists them). They can be used in all the segments. A double click on the box opens the Global declarations dialog, with three tabs:

  • Libraries: files to include (#INCLUDE file in ADbasic; <file.h> or "file.h" in C);
  • Constants: name, value and comment of each constant (#DEFINE in ADbasic, #define in C);
  • Subroutines: name, parameters and body of subroutines (SUB ... ENDSUB in ADbasic, void name(...) {...} in C).

Names must start with a letter or "_" and contain only letters, digits and "_"; they cannot be the name of a channel, of a variable or of a predefined constant. Selected declarations can be copied and pasted into the dialog of another process; text containing declarations can also be pasted.

Source code tab

The last tab shows the code generated from the blocks, the global declarations and the DACQ configuration. It is read only: modify the blocks to change it. Compilation errors are marked in the margin. Ctrl+F (Cmd+F on macOS) opens a find dialog. The generated code can also be opened in the editor of the system with the Open with system editor command of the context menu.

Compilation

A process must be compiled before it can be run. Compilation is automatic when the process is saved and Options > Build automatically is checked; otherwise use Compile in the context menu or Options > Compile... Compilation uses the paths given in the General tab of the DACQ configuration. Errors are written in the Console view and shown with an error overlay on the process; warnings about the blocks structure are shown with a warning overlay.

Once compiled, a process can be tested on its own before being associated with trials.
