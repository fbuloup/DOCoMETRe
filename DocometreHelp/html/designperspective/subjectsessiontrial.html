Subjects, Sessions and Trials

The experimental protocol is described in the Experiments view by a tree of three levels:

  • a subject is a participant of the experiment. It is created in an experiment or in a folder and contains sessions;
  • a session is a set of trials run in sequence (for example a familiarization session followed by a test session). It contains trials and possibly a parameters file;
  • a trial is one run of a process. It is associated with the process to run and, once run, contains the diary and the data files of this run.

Subjects

Select an experiment or a folder, then use File > New > Subject (or the corresponding tool bar button) and give the name and the description of the subject. The label of a subject in the Experiments view gives the percentage of its trials already done, for example Subject1 [25%].

Subjects can also be created from data acquired by other systems (ADW files, Optitrack files, data organized in columns): see Import and export.

Sessions

Select a subject, then use File > New > Session. The wizard has two pages. The first one asks for:

  • the name and the description of the session;
  • the number of trials to create;
  • how to name the data files of the trials (see Data files): "Use this prefix", "Use session name as suffix" and "Use trial number as suffix". An example of file name is displayed.

The second page, Organize this session, associates processes with the trials (see below). The session and its trials are created when Finish is pressed.

The properties and the organization of an existing session can be changed with Edit session in the context menu (or Edit menu).

Sessions can also be imported from a text file that describes them (trials, start and validate modes, processes): select a subject, use File > Import... and choose "Sessions configuration file". The format of this file is described in What is file format for sessions importation ?.

Organization of the trials

The Organize this session page lists, on the left, the processes of the experiment (Available processes). Move the processes you want to use to the Selected processes list (Add selection, Add all, Remove selection, Remove all), then assign them to the trials with one of the two tabs:

  • Assign by trials selection: type the list of trials concerned, for example 1-10,12,14,20-25, and choose to assign them according to the list of selected processes (in order, cyclically), to a random distribution, or to a random distribution without identical consecutive trials;
  • Assign by packet trials: give a packet size (number of consecutive trials); each packet of trials gets one process, according to the list of selected processes or to a random distribution.

Press Apply to compute the association: the Results list shows the process of each trial. Trials can also be associated with a process later, with the Associate with... sub-menu of the context menu.

Trials

Trials are folders named Trial n°N (Essai n°N in French), where N is the trial number. They are created with their session, or with File > New > Trial(s) when a session is selected: type Trial n°10 to create trial 10, or Trial n°10:30 to create trials 10 to 30.

The label of a trial gives its modes and its associated process, for example Trial n°3 [S.Man.][V.Auto.] [/MyExperiment/MyProcess], and its icon shows whether it has been done:

Property Values Meaning
Start mode S.Man. (default) or S.Auto. (D.Man. / D.Auto. in French) Manual: before this trial is started, a dialog asks "Do you want to start next trial ?". Automatic: the trial starts as soon as the previous one is over.
Validate mode V.Man. (default) or V.Auto. Manual: at the end of the trial, a dialog asks "Do you want to validate this trial ?" with the answers Yes (the trial is marked as done), No (the trial stays undone and the next trial is prepared) and No and redo it now (the trial is run again). Automatic: the trial is marked as done without question.
State done or undone A trial is done once it has been validated. Done trials are skipped when trials are run in sequence.
Associated process path of a process Process run by the trial. A trial without process cannot be run.

These properties are changed with the following commands of the context menu, which apply to the selected trials or to all the trials of the selected sessions:

  • Toggle trials states, Mark trials as done, Mark trials as undone: for example to run again trials already done;
  • Toggle trials start modes, Start trials automatically, Start trials manually;
  • Validate trials automatically, Validate trials manually;
  • Associate with...: associates the selected trials with a process;
  • Delete diary and data files...: removes the results of the selected trials, sessions or subjects (this cannot be undone).

The options of the Trials parameters group (Options > Preferences... > General) apply to all the trials: "Validate trials automatically" and "Start trials automatically" override the modes of the trials, while "Stop trial immediately when asked" and "Do not ask for confirmation when stopping a trial" define what happens when a running trial is stopped.

Running subjects, sessions and trials

Subjects, sessions and trials are run in the Acquire perspective, after being selected in the Experiments view (or with the Select item to run button):

  • a trial runs this trial;
  • a session starts with its first trial not yet done;
  • a subject starts with its first trial not yet done.

The run then goes on with the next trials not yet done of the session, according to their start and validate modes, until all the trials of the session have been done, or until the run is stopped or paused. The percentages displayed in the labels of the session and of the subject are updated as trials are done.

Data files

At the end of a trial, the trial folder contains:

  • the diary of the trial, diary.log (journal.log in French);
  • one samples file per recorded channel or variable (Rec. column of the DACQ configuration), which contains its values as 32 bits floating point numbers (see How to open samples data files with Matlab or Python ?).

The name of a samples file is made of the name of the channel and, according to the options of the session, of a prefix and suffixes separated by dots:

[prefix.]ChannelName[.SessionName][.TN].samples

For example, with the prefix S01, both suffixes, the channel Force, the session Learning and trial 12: S01.Force.Learning.T12.samples. Prefixes and suffixes are useful to keep unique names when data files of several sessions or subjects are gathered outside DOCoMETRe. When a session is renamed, DOCoMETRe can also rename its data files.

A double click on a samples file opens it in the data editor. For processing in the Analyse perspective, subjects are loaded by the math engine from these files.

Parameters files

With ADwin systems, variables of the DACQ configuration can be declared as parameters (see the Variables tab). Their values are then sent to the real time system just before each trial starts. A single process can thus be used for several experimental conditions (target position, perturbation amplitude, delay...), the conditions of each trial being given in a parameters file.

To create a parameters file, select a session and use File > New > Parameters file... The new file (*.params) is created in the session with explanations in comments. Each session whose trials use parameters must contain one parameters file.

The file is a text file:

  • "#" starts a comment, until the end of the line;
  • the first uncommented line gives the names of the parameters;
  • the following uncommented lines give the values of the parameters for trial 1, trial 2, etc.;
  • values are separated by ";", "," or ":".
# Target position (cm) and perturbation (0/1)
target;perturbation
10;0
15;0
10;1

See What is parameters file format ? for more details. A double click on a parameters file opens it in the parameters editor, which has two tabs: Fichier brut (the raw text of the file) and Tableau (a table of the values, with buttons to add lines after the selected lines and to remove the selected lines).

Before each trial, the line of the trial is read and the value of each parameter is pushed to the real time system. The trial is not run, and an error is reported, when the session has no parameters file, when a parameter of the configuration is not found in the first line, or when the file has no line for the trial.

When a parameter is propagated, its value at the end of a trial is read from the real time system and written in the parameters file, in the line of the next trial. This is useful to keep and update a value along a session (an adaptive threshold, for example). As values are written back by line number, avoid comment lines between the lines of values of a file that contains propagated parameters.

Parameters are only available with ADwin systems. When a process is tested on its own, parameters values are asked in a dialog.

Diaries (log files)

Each run of a process writes an events diary (*.log file):

  • for a trial: diary.log in the trial folder;
  • for a process test: ProcessName_diary.log next to the process.

The diary is replaced each time the trial or the process is run again. A double click opens it in the diary editor, a read only text editor with line numbers. Errors detected during the run (data losses, communication errors) are marked in the left margin and in the overview ruler on the right (hover over the marker to read the message); the diary, the trial and its parent folders are then decorated with an error overlay in the Experiments view. In the diary editor, Ctrl+F opens a find dialog and Ctrl+= / Ctrl+- increase or decrease the font size (Cmd instead of Ctrl on macOS).

ADwin diaries

An ADwin diary reports the communications between the computer and the ADwin system during the run:

Line Meaning
ADWin booted / ADWin was already booted, Loading ... Start up of the system and loading of the compiled process.
Time since last process stopped Time elapsed since the end of the previous run.
Starting ... at ... sec. Start of the process.
Time between two adwin dialogs Period of the exchanges between the computer and the system.
Recovering channel number : N (name) - Buffer size : n Number of samples of a channel transferred from the system to the computer during an exchange.
Init. generation buffer, Generating channel number : N (name) Samples of a stimulus sent to the system.
Recovery time, Generation time, Display time Time spent to transfer samples, to send stimulus samples and to update the real time charts.
Data loss for channel number : N (name) at t Samples have been lost: the computer did not read them fast enough. This line is marked as an error, with the advice to increase the buffer size (B.S.) of the channel.
No more data to generate for ... The stimulus file is shorter than the run.
Ending ... at ... sec., Approximative ... duration is ... End and duration of the process.

When an ADwin diary is displayed, the diary editor adds statistics to the lines: the running Mean of the times (time between dialogs, recovery, generation and display times) and the running Total of the samples recovered or generated for each channel.

Arduino diaries

An Arduino diary gives the date, the time since the last run, the start time of the process, the list of transferred channels and, about every second, the total number of samples transferred for each channel with the time and the workload of the board. It ends with the messages exchanged to stop the board. Lines starting with "ERROR" report messages received from the board that could not be decoded; they are marked as errors.

Other messages (information, warnings and errors of DOCoMETRe) are written in the Console view.
