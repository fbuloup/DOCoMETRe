DACQ Configuration

A DACQ (data acquisition) configuration file (*.daqconf) describes the real time system used for an experiment: how to reach it from the computer, the global frequency of its real time loop, its modules and their channels, the variables used by the processes and the charts displayed in real time during acquisition. Each process is associated with one DACQ configuration and can only use the channels and variables declared in it.

Creating a DACQ configuration

Select an experiment or a folder in the Experiments view, then use File > New > DACQ Configuration (or the corresponding tool bar button, or the New sub-menu of the context menu). The wizard asks for:

  • the name of the configuration and its description;
  • the system: ADWin or Arduino UNO;
  • whether this configuration must be the default one of the experiment ("Set this DAQ Configuration as default"): the default configuration is pre-selected when a new process is created.

The new configuration is initialized with the default system configuration defined in the preferences (Options > Preferences... > Systems > Default ADWin System or Default Arduino Uno System). Configuring these preferences once for your laboratory avoids typing paths, addresses and modules again for each new configuration.

The DACQ configuration editor

A double click on a configuration opens its editor. It is made of several tabs, displayed at the bottom of the editor:

  • General: access to the system, global frequency and list of modules;
  • Charts: real time charts displayed in the Acquire perspective;
  • Variables: variables of the real time system;
  • one tab per module declared in the General tab (analog inputs, analog outputs, digital inputs/outputs...).

Each field shows a tooltip that explains it. A field with an invalid value is decorated with an error icon, and the error overlay is shown on the editor tab and on the configuration in the Experiments view. Most modifications can be undone (Edit > Undo). Save the configuration with Ctrl+S (Cmd+S on macOS): when Options > Build automatically is checked, all the processes associated with this configuration are compiled again.

General tab

The General tab has two sections: the general parameters of the system and the list of its modules. Its title bar contains a Set this configuration as default button which copies the current values into the preferences (Default ADWin System or Default Arduino Uno System): they will be used to initialize the next configurations.

ADwin systems

Field Description
ADBasic compiler path Path to the ADbasic compiler (installed with the ADwin software).
Bootloader file path Path to the boot loader file (*.btl) that matches the processor of the system.
ADBasic libraries path Folder of the DOCoMETRe ADbasic libraries (read only, use the Browse... button). A warning is displayed when these libraries are older than the version of DOCoMETRe.
ADBasic version Major version of ADbasic.
TCPIP server device number Only required when the computer is not directly connected to the ADwin system.
ADWin device IP address IPv4 address of the system (usual case of a direct Ethernet connection). Browse... searches the reachable devices of the network.
ADwin device TCPIP port, ADwin device number Port and device number as declared in the ADwin driver installation (ADconfig).
Time Out value (in msec.) Time out of the communications between the computer and the system.
Device type, CPU type ADwin Pro or Gold, processor I or II.
Global Frequency Frequency of the real time loop (see below).

The title bar of the tab also contains a Calibration, monitoring button (see below).

The Modules configuration section lists the modules of the system. Use the "+" button to add modules (a dialog lists the available types: Analog inputs, Analog outputs, Digital inputs/outputs, RS232, CAN) and the "x" button to delete the selected modules. For each module, the table gives:

  • Module Type;
  • Module number: address of the module in the system. Two modules of the same type must have different numbers;
  • Module revision: A, B, C...

Each module added in this table gets its own tab in the editor.

Arduino Uno systems

Field Description
Arduino Uno Libraries path Folder of the DOCoMETRe Arduino libraries.
Builder path, AVRDude path Paths to the arduino-builder and avrdude tools of the Arduino IDE, used to compile and upload the processes.
Use command line tool When checked, the arduino-cli tool is used instead of arduino-builder and avrdude. Its path is then given in arduino-cli path.
Revision Revision of the board: R3 or R4_WIFI (Arduino Uno R4 WiFi).
Serial port name Serial port of the board, for example COM3 or /dev/cu.usbmodem1101. Browse... lists the available ports.
Baud rate Speed of the serial link.
Global Frequency Frequency of the real time loop (see below). If the requested frequency cannot be obtained exactly with the timers of the board, a message gives the frequency that will actually be used.

The Modules section lists the modules of the board: Analog inputs, Analog outputs, Digital inputs/outputs and ADS1115 modules (four 16 bits analog inputs on the I2C bus, up to four modules).

Global frequency

The global frequency is the frequency of the real time loop: the Event (or Loop) segment of the processes is executed once per period. The sample frequency of each channel or variable must be a sub-multiple of the global frequency. Click on the link that displays the global frequency to change it.

Modules tabs

Each module tab is made of a general configuration section for the module (when it has parameters), an explanation section, and a channels configuration table where channels are added ("+" button) or deleted ("x" button). The following columns are common to most channels:

Column Description
Name Name of the channel. It is used in processes, in charts and as the name of the samples file. It must be unique in the configuration.
S.F. Sample frequency of the channel, sub-multiple of the global frequency.
C.N. Channel number: physical input or output of the module.
T Transfer: values of the channel are transferred from the real time system to the computer (needed to display or record them).
A.T. Auto transfer (ADwin): the transfer code is generated automatically. Otherwise, place Transfer functions in the processes.
T.N. Transfer number: unique number used for the transfer, generated automatically.
Rec. Record: transferred values are saved in a samples file (ChannelName.samples) in the trial folder.
B.S. Buffer size: size of the buffer used to transfer samples. Increase it when the diary reports data losses.

Specific parameters of each type of module:

Module Specific parameters
Analog inputs (ADwin) Module: maximum and minimum amplitude (±10V, ±5V or 0-10V), single ended or differential inputs.
Channels: Gain (1, 2, 4 or 8), and calibration values: Unit (physical unit of the sensor), UMax / UMin (values in physical unit) and AMax / AMin (corresponding values in electrical unit).
Analog outputs (ADwin) Module: maximum and minimum amplitude.
Channels: Stimulus, checked when output values are read from a stimulus file (see the Stimulus function of the processes and How to create stimulus file with Matlab or Python ?).
Digital inputs/outputs (ADwin) Channels: Inp./Out. (input or output) and Stimulus (for outputs). On ADwin Gold and ADwin Pro DIO32 Rev. B, channels 1 to 16 are inputs and 17 to 32 are outputs.
CAN (ADwin) Name, interface number, system type (CODAMOTION, OPTITRACK, GYROSCOPE, TIMESTAMP, their combinations, or NOT SPECIFIED), frequency, markers number (Codamotion and Optitrack), mode, message objects and identifiers. When the system type is specified, the channels are created and handled by DOCoMETRe (baud rate forced to 1 Mbit/s, global frequency of at least 15kHz). With NOT SPECIFIED, the ADbasic code must be written in the processes.
RS232 (ADwin) Name, interface number, system type (ICE or NOT SPECIFIED), frequency (the global frequency must be a multiple of it), transfer speed, data bits, stop bits, parity and flow control. The channels table lists the channels sent through the serial link ("+" opens a dialog to select them).
Analog inputs (Arduino) Module: Analog reference (DEFAULT, INTERNAL, EXTERNAL for R3, AR_DEFAULT, AR_EXTERNAL for R4).
Channels: Used (the channels of the board are listed; check the ones you use), calibration values (Unit, UMax, UMin, AMax, AMin).
Analog outputs, digital inputs/outputs (Arduino) Channels: Used, and for digital channels Inp./Out. (input or output).
ADS1115 (Arduino) Module: I2C address (0x48, 0x49, 0x4A or 0x4B), mode (0: continuous, for one channel; 1: single shot, recommended for several channels) and conversion time (0 to 7, 7 being the fastest, about 2.7ms).
Channels: Used, Gain of the amplifier (0 for 2/3, 1, 2, 4, 8 or 16) and calibration values.

When a channel is removed or no longer transferred, the curves that display it in the Charts tab are removed. After a modification of the calibration values, recompile the processes associated with the configuration.

Variables tab

Variables are memory spaces of the real time system that processes use to implement their algorithms (counters, states, computed values...). They can also be transferred and recorded like channels. The table of the Variables tab gives, for each variable:

Column Description
Name, S.F., T, A.T., T.N., Rec., B.S. Same meaning as for channels (A.T., T.N. and B.S. are only used with ADwin).
Type ADwin: float, int or string. Arduino: bool, char, int, long or float.
Size 1 for a scalar, more for an array. Arrays cannot be transferred.
Parameter (ADwin) The variable is a parameter: its value is set before each trial, from the parameters file of the session (or from a dialog when a process is tested). Parameters are used to build generic processes, for example one process for several experimental conditions. A parameter cannot be an array and is not transferred.
Propagate (ADwin) For a parameter: its value at the end of a trial is written in the parameters file as the value of the next trial.
Stimulus (ADwin) Values of the variable are read from a stimulus file.

Charts tab

The Charts tab defines the charts displayed in the Acquire perspective while a process associated with this configuration is running. It has two sections.

The Charts section lists the charts. Its buttons add a chart (a dialog asks for its type), delete the selected charts, move the selected chart up or down and configure the charts layout (number of columns, horizontal and vertical span of each chart, order of the charts). The following types of charts are available:

Type Description and properties
Oscillo. Chart Signals as a function of time. Time width (seconds), auto scale or maximum and minimum amplitudes, font, display of current values.
XY Chart A signal as a function of another one (both with the same sample frequency). X and Y maximum and minimum amplitudes, auto scale, history size.
XYZ Chart 3D trajectory of three signals. Requires the "SWT + OpenGL v2" real time chart library (General preferences).
Cursor 2D Chart Last (x, y) values only, drawn as a symbol (circle, square, diamond, triangles, plus, cross, star or image) whose size and colors are configurable, for example to show a target and a cursor to a subject. Requires the "SWT + OpenGL v2" library.
Gauge Chart, Tank Chart Current value of a signal on a gauge or a tank. Minimum and maximum values, and Low Low, Low, High, High High thresholds that can be shown.
Image Chart Images whose generic file name is given; they must be present in the session folders. This type of chart is still being developed.

The Curves section lists the curves of the selected chart. Its buttons add curves (a dialog lists the transferred channels and variables) or delete the selected ones. For each curve, the table gives the channel name (X, Y and Z channels for XY and XYZ charts), its color, its line style and width, and the specific properties of the chart type (symbol of a cursor 2D chart, for example).

Calibration and monitoring (ADwin)

The Calibration, monitoring button of the General tab opens a dialog that shows the inputs and outputs of the system. After the proceed button has been pressed, the inputs are monitored and the outputs take the values given in the dialog: set these values before starting the monitoring. For each analog input, the minimum and maximum electrical values can be captured from the current value (buttons Capture Min Value and Capture Max Value) or typed (validate with Enter), and the corresponding physical values typed: they become the calibration values (UMin, UMax, AMin, AMax) of the channel. "Show calibrated values" displays the values in physical unit. When the calibration has been modified, do not forget to save the configuration and to recompile the associated processes.
