Supported DACQ Systems

A DACQ (data acquisition) system is the real time hardware that acquires the signals of an experiment and generates its outputs. DOCoMETRe generates the program of this hardware from the processes you design, compiles it, loads it in the system, then receives the transferred samples during each trial. Two families of systems are supported: ADwin and Arduino Uno.

Overview

Arduino Uno R3, Uno R4 WiFi, with up to four ADS1115 modules USB (serial link) Windows, Linux, Mac OS arduino-cli (or arduino-builder and avrdude for Uno R3), ADS1X15 library for ADS1115 modules

Other systems are being considered but are not available yet: see Planned systems.

Which system should I choose ?

ADwin Arduino Uno
Real time loop Several kHz to tens of kHz, very stable (dedicated real time processor) Typically a few hundred Hz, up to about one kHz with few channels: limited by the serial link and the work done in each period (see Timing consideration)
Analog inputs 16 bits, ±10V, ±5V or 0-10V, gains 1 to 8, single ended or differential 10 bits (R3) or 14 bits (R4 WiFi), 0-5V; 15 useful bits with ADS1115 modules
Analog outputs 16 bits, stimulus files PWM outputs (8 bits); one 12 bits DAC output with the Uno R4 WiFi
Floating point computations, filters, calibration Yes Limited (no floating point unit on R3), no calibration tool
CAN and RS232 interfaces (Codamotion, Optitrack, gyroscopes, ICE...) Yes No
Cost, ease of installation Expensive, requires the ADwin software Cheap, only requires the Arduino tools

In short: choose ADwin for demanding experiments (high frequencies, precise timing, many channels, external motion capture systems), and Arduino Uno for simple, low cost or portable set-ups.

Declaring a system in DOCoMETRe

A system is declared in a DACQ configuration: choose the system when you create the configuration, then fill its General tab (how to reach the system, paths of the compilation tools, global frequency) and its modules tabs. The default values of new configurations come from the preferences pages Default ADWin System and Default Arduino Uno System. The pages of this section describe what has to be installed and checked for each system before filling this configuration.
