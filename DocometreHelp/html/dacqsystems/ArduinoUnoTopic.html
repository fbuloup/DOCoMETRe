Arduino Uno R3 and R4 WiFi

Two revisions of the Arduino Uno are supported. Choose the one of your board in the Revision field of the DACQ configuration. Read Arduino DACQ Systems first for the installation of the Arduino tools and the connection of the board.

The Uno R4 Minima is not supported. When an experiment moves from an R3 to an R4 WiFi (or the reverse), change the Revision field, check the analog reference (converted automatically), the variables (size of int, reserved names) and the analog outputs (the DAC output AOUT_DAC exists on the R4 WiFi only), then compile the processes again.

Inputs and outputs

The modules of an Arduino Uno are created automatically with the configuration: you only check the Used column of the channels you need. ADS1115 modules are the only modules you can add (see ADS1115 Module).

Module Channels Board pins Remarks
Analog inputs AIN0 to AIN5 A0 to A5 0 to 5V with the default reference. Calibration values (Unit, UMax, UMin, AMax, AMin) convert the values in physical units. On the R3, a conversion takes about 19µs.
Analog outputs AOUT3, AOUT5, AOUT6, AOUT9, AOUT10, AOUT11 digital pins 3, 5, 6, 9, 10, 11 PWM outputs (values 0 to 255), not true analog outputs: add an RC filter if you need a continuous voltage.
Analog outputs (R4 WiFi only) AOUT_DAC A0 True analog output of the 12 bits DAC of the R4 WiFi (values 0 to 4095, 0 to about 5V with the default reference). The channel is added to the analog outputs module when the revision of the board is R4 WiFi. Pin A0 is also the analog input AIN0: only one of them can be used.
Digital inputs/outputs DIGITAL0 to DIGITAL13 digital pins 0 to 13 Inp./Out. column: input, output or input_pullup (input with the internal pull-up resistor, for switches connected to the ground).

Remarks:

  • a pin used as an analog output (PWM) can't be used as a digital input or output at the same time, and pin A0 can't be used both as analog input AIN0 and as DAC output AOUT_DAC (R4 WiFi);
  • on the Uno R3, digital pins 0 and 1 are the serial link with the computer: do not use DIGITAL0 and DIGITAL1, the transfer of the samples would be disturbed. On the R4 WiFi the serial link with the computer doesn't use these pins, which are free;
  • pin 13 is connected to the LED of the board.

Analog outputs in processes (PWM and DAC)

An analog output is used like a variable: in a process, give a value to its channel name with the Compute expression(s) function (for example AOUT_DAC = 2048). The value is written on the output at the sample frequency of the channel, and sent to the computer if the channel is transferred.

Channels Values Output
AOUT3, AOUT5, AOUT6, AOUT9, AOUT10, AOUT11 0 to 255 PWM signal whose duty cycle is value/255: add an RC filter to get a continuous voltage.
AOUT_DAC (R4 WiFi only) 0 to 4095 Continuous voltage on pin A0, from 0V to about the voltage of the analog reference (about 4.8V measured with the default reference): value 2048 gives about half of it.

With AOUT_DAC:

  • check Used for AOUT_DAC in the analog outputs tab of the DACQ configuration (revision R4 WiFi), then compile the processes again;
  • the analog input AIN0 can't be used at the same time (same pin A0);
  • the DAC is written in 12 bits and the PWM outputs stay in 8 bits: the generated code sets the resolution of analogWrite to 12 bits only around the write of the DAC, because this resolution is common to all the analog outputs of the R4 WiFi. In your own functions, write the DAC the same way (analogWriteResolution(12), analogWrite(A0, value), analogWriteResolution(8)): with the default 8 bits resolution, values over 255 give 0V;
  • do not change the mode of pin A0 (pinMode) in your own functions: on the R4 WiFi, the pin is no longer connected to the DAC when its mode is changed after its first write.

At the end of each trial, the analog outputs are set to 0 (0V for the DAC). The values of the outputs can be checked with the calibration and monitoring dialog.

Choosing the global frequency

The real time loop is called by a timer interrupt at the global frequency. On the Uno R3, the period is obtained by dividing the 16 MHz clock: when the requested frequency can't be obtained exactly, a message gives the frequency that will actually be used. Prefer frequencies that are multiples of powers of 2 and/or 10 (100Hz, 200Hz, 500Hz, 1000Hz...).

The maximum usable frequency depends on the work done in each period (number of channels acquired, computations, lines sent on the serial link): check the workload displayed during a test or a trial (see Testing a Process). It must stay well below 100%. Remember that the sample frequency of each channel must be a sub-multiple of the global frequency.

Variables and reserved names

The names of the channels and variables of the DACQ configuration become names of the generated C++ code. They must not be names already used by Arduino, by the C library or by DOCoMETRe (for example F, PI, signal, time on R3, rtTime on R4 WiFi...): see the list in Troubleshoots with Arduino Uno system. Variables can be of type bool, char, int, long, float or string.

Calibration and monitoring

The Calibration, monitoring button of the General tab shows the values of the used inputs and sets the values of the used outputs (0 to 255 for PWM outputs, 0 to 4095 for the DAC of the R4 WiFi). It is used to check the wiring and to compute the calibration values of the analog inputs, as with ADwin systems: see Calibration and monitoring.

Like the calibration programs of ADwin systems, the calibration firmware is precompiled: it is the same for all the DACQ configurations and is not compiled on your computer, it is only uploaded (with avrdude, or arduino-cli for the R4 WiFi which requires it). It is configured by DOCoMETRe through the serial port, at 115200 bauds whatever the baud rate of the DACQ configuration. Its sources and the way to compile it again are in the Libraries plugin (includes/ArduinoUnoCalibrationFiles).

The values of the analog inputs are converted in volts from the analog reference: 5V for DEFAULT (R3) and AR_DEFAULT (R4 WiFi), 1.1V for INTERNAL (R3), 1.5V for AR_INTERNAL (R4 WiFi), full scale of the gain for ADS1115 inputs. With EXTERNAL and AR_EXTERNAL, the voltage of the AREF pin is not known: raw values of the converter are displayed (0 to 1023 on R3, 0 to 16383 on R4 WiFi).

The calibration values are saved in the DACQ configuration. The data of the trials are still recorded as raw values of the converters.

If something goes wrong, see Troubleshoots with Arduino Uno system.
