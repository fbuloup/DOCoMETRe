Troubleshoots with Arduino Uno System

I am on Linux and can't see Arduino Uno port. What can I do ?

On linux OS, an Arduino Uno is usually connected to /dev/ttyACMn. But if you do not have right access to /dev/ttyACMn, you won't be able to use it in DOCoMETRe. In order to access this device, please run these commands in terminal : 

   sudo usermod -a -G tty UserName
   sudo usermod -a -G dialout UserName
   sudo chmod a+rw /dev/ttyACMn

These commands simply add UserName to tty and dialout groups and make sure UserName has read and write acces to /dev/ttyACMn. Please follow this link if you need more informations. You must obviously use proper values for UserName and n.

My Arduino Uno processes using ADS1115 module doesn't compile.

If you get this kind of error message :

fatal error: ADS1X15.h: No such file or directory
 #include "ADS1X15.h"
                     ^
compilation terminated.
exit status 1
Erreur de compilation pour la carte Arduino/Genuino Uno

It means that you need to install ADS1115 driver from Rob Tillaart as build-in Arduino Uno Library. To do so, please follow this github link : ADS115 Library. Then click on Download Button and choose Download ZIP Menu Item. Once Zip file has been downloaded and uncompressed, rename corresponding folder to ADS1115 and cut/past it in Java/libraries folder of your Arduino Uno IDE installation directory. You can also install this library from Arduino IDE direclty. If you choose this option, please follow this link to find a tutorial on installing additional libraries : Installing Additional Arduino Libraries. Compilation should now occur without any error.

My Arduino Uno process doesn't compile : "redeclared as different kind of symbol" or "multiple definition of".

If you get this kind of error message (here with an Uno R4 WiFi) :

procArduino.ino:76:5: error: 'int F' redeclared as different kind of symbol

or, when the program is linked :

signal.c:(.text.signal+0x0): multiple definition of `signal'
procArduino.ino:78: first defined here
collect2.exe: error: ld returned 1 exit status

It means that the name of a variable or of a channel is already used. The names of the variables and of the channels of the DACQ configuration become names of the generated C++ code (the sketch) : they must not be names already defined by Arduino, by the C library or by DOCoMETRe. A name can be accepted with a board and refused with another one : for example F is a macro with R3 but a function with R4 WiFi, and signal is a function of the C library of R4 WiFi only. Rename the variable or the channel (in the DACQ configuration, in the processes and, for a parameter, in the first line of the parameters files) and compile again. Here are examples of reserved names :

  • Arduino functions, macros and constants : F, PI, HALF_PI, TWO_PI, HIGH, LOW, INPUT, OUTPUT, A0 to A5, DEC, HEX, BIN, abs, min, max, round, sq, constrain, map, bit, word, delay, millis, micros, random, Serial...
  • Functions of the C library : signal, exit, abort, sin, cos, tan, exp, log, pow, sqrt, time (R4 WiFi)...
  • Keywords of the C++ language : int, long, float, char, bool, new, delete, class, return, switch...
  • Names of the code generated by DOCoMETRe : time (R3), rtTime (R4 WiFi), workload, timeIndex, startLoop, terminateProcess, restartRequested, loopFrequency, loopPeriod, serialMessage, sendTimeWorkload, and, with parameters, parameterLine, parametersReceived, parameterError, PARAMETERS_COUNT, propagationInProgress...

My trial doesn't start : "Parameters not acknowledged by the Arduino Uno" or "The parameters of the process have changed since its compilation".

Before the start of a trial, the values of the parameters are sent to the Arduino, which must acknowledge them (see How are parameters sent to the DACQ system ?). The trial is not started when :

  • the process has been compiled before the parameters of its DACQ configuration were added, removed or reordered (the Arduino answers N0) : compile the process again, it will be uploaded at the next start;
  • the Arduino doesn't answer : check the connection of the board, then compile and upload the process again (a process compiled with a version of DOCoMETRe without parameters management can't receive them);
  • the Arduino refuses a value (N<n>, n being the rank of the parameter) : check the value of this parameter in the parameters file.

The message "The parameters of the process have changed since its compilation" can also be written in the diary of a trial : the process expects parameters which were not sent. Compile the process again.

The diary says "Values of the propagated parameters not received from the Arduino Uno".

At the end of a trial, the Arduino sends the values of the propagated parameters and the PC acknowledges them. When they are not received (process compiled before the propagation was configured, communication issue, stop of the trial), the parameters file is not modified : the next trial uses the value written in the file. Compile the process again if its configuration has changed, and check the parameters file before going on with the session.

Arduino Uno R4 WiFi : the process starts, then nothing ("Arduino stop reply ('s') not received", "Arduino restart ('w') not received").

On the Uno R4 WiFi, the real time loop of the process runs in a timer interrupt, and Serial is a serial link (UART) with the ESP32 of the board. Writing on Serial in the real time loop blocks the board: the write waits for the end of the transmission. The code generated by DOCoMETRe puts the messages for the computer in globalSerialMessage, sent by loop() outside the interrupt. In your own functions (user functions, expressions), do the same : globalSerialMessage += text; (add "\n" at the end of a line), and never Serial.print, noInterrupts() or dynamic memory (String). Processes compiled with a previous version of DOCoMETRe which transfer analog outputs (PWM or AOUT_DAC) or ADS1115 inputs must be compiled again.

Calibration, monitoring : "The calibration firmware does not answer" or "Upload of the calibration firmware failed".

  • Check the serial port (Device path) and the revision (R3 or R4 WiFi) of the board in the General tab of the DACQ configuration, and that no other program (Arduino IDE serial monitor for example) uses the serial port.
  • Check the upload tool : avrdude (R3) or arduino-cli (R3 or R4 WiFi, required for the R4 WiFi) and its path in the General tab, as for the upload of the processes.
  • "The calibration firmware refused the command S0x48..." : the ADS1115 module at this address does not answer on the I2C bus (wiring, address).
  • After a calibration, the acquisition process is uploaded again at the next trial : this is normal, the calibration firmware had replaced it on the board.
