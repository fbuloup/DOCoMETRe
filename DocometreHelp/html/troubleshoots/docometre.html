Troubleshoots with DOCoMETRe

How to debug timing during acquisition ?

When trials follow one another, you may want to know how long DOCoMETRe takes between the end of a trial and the start of the next one, and where this time is spent (charts creation, files, boot of the system...). To get these measures, add -traceTrialTimings argument to program command line.

This argument is a program argument, not a Java virtual machine one : in DOCoMETRe.ini file, it must be on its own line before the -vmargs line :

-startup
../Eclipse/plugins/org.eclipse.equinox.launcher_1.6.100.v20201223-0822.jar
--launcher.library
../Eclipse/plugins/org.eclipse.equinox.launcher.cocoa.macosx.x86_64_1.2.100.v20210209-1541
-traceTrialTimings
-vmargs
--add-modules=ALL-SYSTEM
-Xmx2048m
-XstartOnFirstThread

As for the debugging options below, take a backup of DOCoMETRe.ini before any change.

Each measure is then written as an information message in the log file of the workspace (workspace/.metadata/.log), prefixed by [TIMING]. These measures are currently made with ADWin systems. Without this argument, nothing is measured nor written : the acquisition is not slowed down.

The following measures are written for each trial :

  • End of the trial : the time origin (t = 0) is the end of the process on the acquisition system. Then a summary of the real-time loop is written (number of iterations, duration of the last and of the longest iteration), as well as the duration of the INIT section of the ADbasic process (if it is unknown, recompile the process).
  • Steps between two trials : for each step (channels files closed, end of the real-time loop job, post execution with diary and markers, trial validation and next trial with its dialogs, process preparation, real-time charts creation, boot of the system, process loading, channels files opening, parameters sent to the system, process start), the duration of the step and the total time since t = 0 are written.
  • Start of the next trial : the delays, after the start of the process, of the first real-time loop iteration and of the first data received (first CAN data and first other data).
  • Process stop : the duration of the first call to stop the process. A call longer than 100 ms is reported as a TIME OUT : the process is then cleared, the system is booted again and the process will be loaded again at next start, which makes the start of the next trial longer.

Remove this argument once the debugging is over, in order to keep the log file small.

How to add Objects Controller messages ?

Simply add -debugObjectHandler argument to program command line.

How to debug with Eclipse Platform ?

In order to get debugging platform infos, you must follow these steps :

  1. Create an options file somewhere in your file system
  2. Add -debug parameter in DOCoMETRe.ini file
  3. Add -Sleak parameter in DOCoMETRe.ini file (optional)

1. Create options file

Create an options files with name options.txt for instance and remember its absolute path. This file should contains these options : 

org.eclipse.ui/debug=true 
org.eclipse.ui/trace/graphics=true
org.eclipse.ui/debug/swtdebugglobal=false
org.eclipse.ui/trace/dragDrop=false
org.eclipse.ui/trace/keyBindings=false
org.eclipse.ui/trace/keyBindings.verbose=false
org.eclipse.ui/debug/showAllJobs=false
org.eclipse.ui/debug/job.stale=false

Depending on what you want to trace/debug, you can toggle either of these options.
Note that the option org.eclipse.ui/debug must be true to enable debugging.
See below a partial list of debugging options.

2. Modify DOCoMETRe.ini to activate debugging

Locate the file DOCoMETRe.ini take a backup and change its content as follow :

-startup
../Eclipse/plugins/org.eclipse.equinox.launcher_1.6.100.v20201223-0822.jar
--launcher.library
../Eclipse/plugins/org.eclipse.equinox.launcher.cocoa.macosx.x86_64_1.2.100.v20210209-1541
-debug
/Path/To/File/options.txt
-vmargs
--add-modules=ALL-SYSTEM
-Xmx2048m
-XstartOnFirstThread
-Dorg.eclipse.swt.internal.carbon.smallFonts

Note the bold lines : this is what you need to change.
Do not change anything else in this file as it could result in errors.

This is why you should have a carbon copy of the original file before any changes.

3. Modify DOCoMETRe.ini to add Sleak feature

Change content of DOCoMETRe.ini file as follow :

-startup
../Eclipse/plugins/org.eclipse.equinox.launcher_1.6.100.v20201223-0822.jar
--launcher.library
../Eclipse/plugins/org.eclipse.equinox.launcher.cocoa.macosx.x86_64_1.2.100.v20210209-1541
-debug
/Path/To/File/options.txt
-vmargs
--add-modules=ALL-SYSTEM
-Xmx2048m
-XstartOnFirstThread
-Dorg.eclipse.swt.internal.carbon.smallFonts
-DSleak

Then refresh all perspectives where you want to use Sleak or Spy views.
