User Functions

When the standard functions library does not provide what you need, or when the same expressions are used again and again, you can write your own functions for the math engine. A user function is a text file (*.FUN) with the same format as the user functions of the acquisition processes (see How to create my own dacq. user function ?), whose code is written in Python or in Matlab.

Where are user functions ?

The functions proposed in the Customer functions sub-menu of the Assign menu of a data processing file are those of the user scripts location of the math engine in use (Options > Preferences... > Math Engine > Python or Matlab, see Math engines). A function file stored elsewhere is not proposed.

Choosing a folder of the workspace (a folder of an experiment, for example) as user scripts location makes the functions visible in the Experiments and Subjects views too, and exports them with the experiment.

Functions view

The Functions view (Options > Show... > Functions View) lists all the functions known by DOCoMETRe, in folders: ADwin functions and user functions, Arduino Uno functions and user functions, Python functions and user functions, Matlab functions and user functions. A double click on a function opens it in the Functions editor: the code of the standard functions can be read there, which is a good starting point for your own functions. New user function in the context menu of a user functions folder creates a new function file in this folder.

Writing a user function

A user function can also be created with the New user function button (in the selected folder of the Subjects or Experiments view). The new file contains USER_FUNCTION = YES. In the Functions editor, Ctrl+Space proposes the keys of the file format and the types of parameters:

KeyDescription
MENU_TITLE (MENU_TITLE_FR...) Title of the function in the Assign menu.
DESCRIPTION (DESCRIPTION_FR...) Tooltip of the function in the menu.
USER_FUNCTION YES for a user function.
PARAMETERS_NUMBER Number of parameters of the function.
PARAMETER_N Definition of parameter N: NAME, TYPE (TEXT, with an initial value and a regular expression to check the value, FILE, FOLDER or COMBO) and LABEL displayed in the configuration dialog.
FUNCTION_CODE Code of the function (lines ended with \n\). Each occurrence of the name of a parameter is replaced by the value given in the configuration dialog.

Example of a Python user function that multiplies a signal by a gain, in place:

MENU_TITLE = Gain
DESCRIPTION = Multiply a signal by a gain
USER_FUNCTION = YES
PARAMETERS_NUMBER = 2
PARAMETER_1 = NAME = signalName, TYPE = TEXT:^(?!\s*$).+$, LABEL = "Signal full name :"
PARAMETER_2 = NAME = gainValue, TYPE = TEXT[1.0]:[+-]?(\d+\.?\d*|\d*\.\d+), LABEL = "Gain :"
FUNCTION_CODE = docometre.experiments["signalName.Values"] = gainValue * docometre.experiments["signalName.Values"];\n\
if not("createdOrModifiedChannels" in docometre.experiments.keys()):\n\
\tdocometre.experiments["createdOrModifiedChannels"] = "signalName";\n\
else:\n\
\tdocometre.experiments["createdOrModifiedChannels"] = docometre.experiments["createdOrModifiedChannels"] + ":signalName";

The last lines tell DOCoMETRe that the signal has been modified, so that the subject is marked as modified (see Compute expression(s)).

Use the full names of signals (Experiment.Subject.Signal, see the Data model) as parameter values; a batch processing replaces the subject in these names. Save the file: the function is then proposed in the Customer functions sub-menu.
