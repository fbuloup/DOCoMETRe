Data Processing Files

A data processing file (*.dataprocess) describes a sequence of operations applied to the signals of loaded subjects: filtering, cuts, markers, features, exports... Like the acquisition processes, it is built with graphical blocks. DOCoMETRe generates from these blocks Python or Matlab code, according to the math engine in use, and runs it in the engine.

Creating a data processing file

Select the experiment (or a folder of it) in the Subjects view and use the New data processing button (or File > New > Data processing). Give its name and its description. The file appears in the Subjects view; a double click opens it.

Data processing editor

The editor has two tabs:

  • Design: the drawing area where blocks are created and linked, with the same palette as the acquisition processes: Connection Creation, If block, Do block, Function block and Comment block (see Palette and blocks). Blocks are executed once, in the order of the connections, starting from the block without incoming connection;
  • Source code: the code generated for the math engine, read only.

A function block is assigned with right click > Assign, then configured with a double click. The Assign menu is organized as follows (see the Standard functions library):

  • Signals: Filtering sub-menu, cuts, motion, absolute value, derivative, interpolation, duplicate, sample frequency, replacement of samples, FFT;
  • Markers: functions that place markers;
  • Features: functions that compute features, with the Complexity sub-menu;
  • Events: no function for now;
  • Export: export of markers and features to CSV files;
  • Compute expression(s): free code (see below);
  • Customer functions: your own user functions.

The other commands of the context menu (copy, paste, toggle activated state, zoom, grid...) are the same as in the acquisition process editor. Deactivated blocks are not run, which is convenient to run only a part of a processing.

Configuring a function

The configuration dialog of most functions contains:

  • Input signal name: the signal to process, chosen among the signals of the loaded subjects (full name Experiment.Subject.Signal);
  • Trials list: the trials to process, numbered from 1, separated by "," or ";", with ranges written "a-b" or "a:b", for example 1-10, 15, 20:25;
  • Output signal suffix name, for functions that create a new signal: the new signal is named after the input signal followed by this suffix (for example ForceLP for the low pass filter of Force). An existing signal with this name is replaced;
  • Markers group label, for functions that place markers: the label of the group in which markers are added;
  • the specific parameters of the function (cut off frequency, order, threshold, from and to markers...).

The input signal is a signal of a given subject: a data processing file is therefore built on one subject. To apply it to other subjects, use a batch processing, which replaces the name of the subject in the generated code.

Compute expression(s)

The Compute expression(s) function inserts your own lines of code (Python or Matlab, according to the engine) in the processing. Its dialog has two tabs: Expressions list, where each expression is typed, then added (Add), modified (select it, change it, Modify), deleted or moved up and down; and Source code, which shows the resulting code. In the Expression field, Ctrl+Space proposes the names of the elements of the loaded subjects (see the Data model). For example, with Python:

D["MyExp.S01.ForceN.Values"] = D["MyExp.S01.Force.Values"] / 9.81

Note that such an expression only adds the Values element: to create a complete signal, also set the other elements described in the data model, or use the Duplicate function first. DOCoMETRe marks a subject as modified from the list of the signals created or modified by the functions: docometre.experiments["createdOrModifiedChannels"] with Python (full names separated by ":"), cell array createdOrModifiedChannels with Matlab. An expression that changes data should add the full name of the signal to this list, otherwise the subject is not marked as modified.

Running a data processing file

  1. Start the math engine and load the subjects whose signals are used by the processing.
  2. Select the data processing file in the Subjects view (several can be selected, they are run one after the other), or activate its editor.
  3. Press Run selected data processes.

A progress dialog is displayed while the code runs in the engine. Errors of the engine are written in the Console view. When the processing is over, the Subjects view and the opened editors are updated: new signals appear under the subject, and markers and features are displayed in the signal editor. Processed subjects are marked as modified: save them to keep the results.

With Python, the tool bar of the data processing editor contains a Run in main thread toggle button. Check it when the processing opens Matplotlib figures (with an expression or a user function): graphical functions of Python must run in its main thread. The file is then decorated with an overlay in the views (see Is it possible to use python Matplotlib or Matlab figures ?).
