Can I use an Arduino Uno with DOCoMETRe running in WSL2 on Windows ?

Yes you can ! With WSL2 (Windows Subsystem for Linux), the Linux release of DOCoMETRe runs in an Ubuntu distribution installed on Windows, and its windows are displayed on the Windows desktop (WSLg). But WSL2 does not see the USB devices of Windows : an Arduino Uno connected to a USB port of the computer must first be shared with WSL2. This is done with usbipd-win, the tool recommended by Microsoft (see Connect USB devices in the WSL documentation, and usbipd-win).

In the commands below, run in PowerShell or in the Ubuntu terminal as indicated, 2-3 is an example of bus identifier (BUSID) : use the one of your board.

1. Install usbipd-win on Windows (once)

In PowerShell run as administrator :

winget install --interactive --exact dorssel.usbipd-win

Nothing has to be installed in Ubuntu with a recent version of WSL : the version of its kernel, given by wsl --version in PowerShell, must be 5.10.60.1 or later.

2. Allow your Linux user to use the serial ports (once)

In the Ubuntu terminal :

sudo usermod -aG dialout $USER

Then restart WSL, in PowerShell, so that this change is taken into account, and open the Ubuntu terminal again :

wsl --shutdown

See also Troubleshoots with Arduino Uno System.

3. Share the Arduino Uno with WSL2

Connect the board and open the Ubuntu terminal. Then, in PowerShell run as administrator, list the USB devices :

usbipd list

Find the line of the Arduino Uno and note its BUSID, for example :

BUSID  VID:PID    DEVICE                       STATE
2-3    2341:1002  USB Serial Device (COM3)     Not shared

Share it (once for each board, as administrator), then attach it to WSL2 :

usbipd bind --busid 2-3
usbipd attach --wsl --busid 2-3 --auto-attach
  • bind is needed only once for each board;
  • attach must be done again each time the board is connected, and each time WSL or Windows is restarted;
  • with --auto-attach, the board is attached again automatically when it is disconnected, which may happen when it resets during an upload. This command keeps running : leave its PowerShell window open.

4. Check in Ubuntu

In the Ubuntu terminal :

ls -l /dev/ttyACM*

The board must appear, usually as /dev/ttyACM0 (a character device of the dialout group). In DOCoMETRe, give this name as Serial port name in the General tab of the DACQ configuration (the Browse... button lists the available ports). Processes can then be compiled, uploaded with arduino-cli and run from WSL2.

Things to know

  • Windows no longer sees the board while it is attached to WSL2 : its COM port disappears, so the Arduino IDE or DOCoMETRe for Windows can't use it. To give it back to Windows (or simply disconnect it), run in PowerShell : 
    usbipd detach --busid 2-3
  • /dev/ttyACM0 must be the real device. If ls -l /dev/ttyACM0 shows a link to /dev/null (placeholder created by the recording scripts of the video tutorials, which need no board), remove it before attaching the board, otherwise the board can't get this name : 
    sudo rm /dev/ttyACM0
    It also disappears when WSL is restarted (wsl --shutdown).
  • Timing. USB/IP transfers the data through the virtual network of WSL2, which adds latency and jitter. This is fine to configure the DACQ system, compile, upload and test processes. For experiments with high sampling frequencies, prefer DOCoMETRe for Windows with the board connected directly (see also Timing consideration).
  • OpenGL charts. WSLg is a Wayland session, whereas the OpenGL charts of DOCoMETRe (e.g. real time charts of a process test) need the X11 backend of GTK : DOCoMETRe restarts itself at startup with the environment variable GDK_BACKEND=x11. With an older version of DOCoMETRe, which closes without warning when such a chart is displayed, start it with this variable : 
    GDK_BACKEND=x11 ./DOCoMETRe
