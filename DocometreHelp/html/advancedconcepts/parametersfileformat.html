What is parameters file format ?

Using parameters in acquisition configuration files is very often a good way to reduce acquisition process files number. Doing so, a set of parameters values will be pushed to the real time process before current trial begins. There is also an option to propagate parameters values from a trial to its next one : it can be useful if you need to keep and update specific values during all session execution. You can configure parameters in Variables tab of the acquisition configuration file. This feature is available with ADwin devices and with Arduino Uno devices (R3 and R4 WiFi). Once these parameters are configured, you must add a parameters file in the root of each session : it's a simple text file you can manage from DOCoMETRe or create elsewhere. You can see below an example of this kind of file : 

 paramName1;paramName2;paramName3
 1;5.25;3.28
 0;4.75;3.28
 1;3.25;3.28
 ...

As you add such a file in each session, you must have at least as many lines as there are trials in the session. Here is the content of a blank parameters file which will give more informations on file format, comments and separator char :

# Welcome in this parameters file !
#
# You can use hashtag character (#) to insert comments.
# Everything to the right of this hashtag will be processed as a comment.
#
# Parameters delimiters can be semicolon (;) or comma (,) or colon (:).
#
# Please note that each uncommented line is associated to a trial of the current session, except for the first uncommented line :
# - The first uncommented line will correspond to the parameters names
# - The second uncommented line will correspond to the first trial
# - The third uncommented line will correspond to the second trial
# etc.
#
# Each uncommented line will be parsed to read the parameter name or value.
#
# Here is a parameters file example (the third parameter is of type string) :
# ParameterName1 ; ParameterName2 ; ParameterName3
# 10.25 ; 5 ; condition-1
# -10.25 ; 4 ; condition-2
# 5 ; 3 ; condition-1
# ...

Parameters configuration

A variable becomes a parameter when its Parameter column is checked in the Variables tab of the DACQ configuration. The same rules apply to ADwin and Arduino Uno :

  • a parameter can't be transferred;
  • only a parameter of type string can be an array : its size is then the maximum length of the string;
  • only numeric parameters can be propagated (not strings).

Columns of the parameters file are associated with the parameters by their names (case is ignored) : they can be in any order and the file can hold other columns. White spaces are removed from the lines : a string value can't contain white spaces, nor the separators ";", "," and ":".

Internally, the number of a parameter is its rank in the list of the variables which are parameters. This number is not displayed, but it is used by the compiled process : compile the process again each time you add, remove or reorder parameters.

Accepted values

Values are checked before the start of the trial (and in the dialog of a process test). With an invalid value, the trial is not run and an error is reported.

intInteger. It is sent to ADwin as a float : values are exact only up to ±16 777 216 (224). Integer on 16 bits with R3 (-32768 to 32767), on 32 bits with R4 WiFi.
long-Integer on 32 bits.

stringAll the string parameters together can't hold more than 1024 characters (otherwise they are not sent and an error is reported). At most Size printable ASCII characters. With R3 (2048 bytes of RAM), a warning is given at compile time when string variables use more than 512 bytes.

Propagation

At the end of a trial, the values of the propagated parameters are read from the DACQ system and written in the parameters file, in the line of the next trial. The other values of this line, its comment and the other lines of the file are kept. Nothing is written after the last trial of the session (no next line), nor when the values could not be read from the DACQ system : the file is then not modified and an error is written in the diary of the trial.

Values are written as a float with ADwin (e.g. 5.0) and in the format of their type with Arduino Uno (e.g. 5 for an int, 1.5 for a float).

When the parameters file is opened in its editor during the session, the editor is reloaded each time the file is changed (see Parameters files).

How are parameters sent to the DACQ system ?

ADwin

  • Before the trial : the values of the numeric parameters (float and int) are written in the DATA_200 array of ADwin, in the order of the numeric parameters of the Variables tab. In the generated ADbasic code, this array is TAB_PARAM : each parameter is set from it at the beginning of the initialization of the process. The values of the string parameters are written together, separated by line feeds, in the DATA_199 array (TAB_PARAM_STRING in the generated code).
  • At the end of the trial (propagation) : the DATA_200 array is read again. Strings are never propagated.

Arduino Uno

Values are exchanged as text lines (frames) on the serial port, in which n is the number of the parameter (its rank in the list of all the parameters) :

FrameMeaning
P<n>:<value>Value of parameter n (bool : 0 or 1, integers in base 10, float in +1.234567E+00 format, char and string as is).
E<count>End of the sending of count parameters.
A<count>Acknowledgement : all the parameters have been received and read.
N<n>Error on parameter n (missing, unknown or invalid value). N0 : the number of parameters is not the one of the compiled process.
  • Before the trial, while the Arduino waits for the start ('r' char), the PC sends the P frames of all the parameters then the E frame. The Arduino writes each value directly in its variable and answers with A or N. The trial is started only when the parameters are acknowledged (1 s of wait, 2 attempts) : otherwise it is not started and an error message is displayed. With 2 parameters, this exchange takes about 2 to 3 ms.
  • At the end of the trial (propagation), the Arduino sends the P frames of the propagated parameters then the E frame, before its end of process ('s' char). The PC answers with A or N (about 500 ms of wait on the Arduino, 2 attempts).

Example with two parameters A (propagated) and Freq :

PC      -> Arduino : P1:500   P2:1   E2
Arduino -> PC      : A2
PC      -> Arduino : r                       (start of the trial)
...
Arduino -> PC      : P1:401   E1             (end of the trial)
PC      -> Arduino : A1
Arduino -> PC      : s

The code generated for a process without parameters is not changed. A process compiled before the parameters of its configuration have been modified answers N0 (or does not answer) : compile and upload it again.
